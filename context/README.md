# context/：部署ごとの業務の地図

ここに部署の地図（`<部署名>.md`）を置くと、その部署の人のセットアップで、Claude がドライブのどこを読めばよいかを最初から知った状態で始められる。地図が無い部署の人は、Claude がパソコンとドライブを読んで、本人用の地図（作業フォルダの `docs/仕事の地図.md`）を一から作る。

## 地図の書き方

`templates/仕事の地図.md` と同じ形で書く。入れてよいもの・入れないもの：

| 入れる | 入れない |
|---|---|
| 組織と役割（名字だけ）、業務の流れ、主なシート・フォルダの名前と URL、タブ・列の意味、用語、今わかっている手作業・困りごと | 売上・利益・単価・給与の金額、個人別の成績や報酬、連絡先・住所・退職理由、メールアドレス、パスワード類 |

シートの URL は載せてよい（共有されていない人は開けない）。中身の数字は書かない。

## 地図を育てる

各メンバーの Claude は、本人の話や実物が地図と違うと気づくと、反映を提案し、週次レビューの「地図の変更提案」に載せる。会社側はそれを見て、ここの地図を直して push する。
